# ShelfRow

**ShelfRow** は、かつて多くのユーザーに愛された macOS 用蔵書管理アプリケーション「**Stackroom**」のコンセプト、資産、および操作性を現代の macOS（SwiftUI / SwiftData）環境へと継承・近代化した、高速かつ軽量な書庫管理ツールを目指して開発しているものです。
今後も、重たくなる機能追加はしない予定です。

### あるもの
 - Stackroomに準拠したインタフェースとファイル操作
 - NASでの運用を前提としたフォルダの一括指定(NAS買い替え時等に便利)
 - Stackroom XML インポート機能と、インポート後の不具合を一括修正する各種機能
 - サムネイル等を含めた一括バックアップ機能

### ないもの
 - ビューアは内蔵していません(お好みのものを使ってください)
 - 昔のiTunes風3ペイン検索も個人的に使っていないので外しました

### 作る予定のもの
 - iPad 版

> [!NOTE]
> 複数の Mac で蔵書を共有する仕組みは **iCloud 同期** として実装済みです。書誌情報だけを iCloud に置き、書籍の実体は NAS に置きます。サムネイルは iCloud に送らず、[NAS 上のフォルダを経由して配布](#-サムネイルの配布nas経由)します。

## 🚀 Stackroom からの移行手順（環境設定 → 保守）

Stackroom で管理していたライブラリ資産（データおよびサムネイル画像）を ShelfRow へ移行・引き継ぎする機能は、画面左下の **⚙️（環境設定）>「保守」** タブに集約されています。

> [!IMPORTANT]
> Stackroom からの移行作業は、アプリ導入時に以下のステップ順に行うことを推奨します。

```
[Stackroom Library.xml] ───(1) XMLライブラリのインポート───► SwiftData データベース
[Stackroom サムネイル]   ───(2) サムネイルの移行─────────► ShelfRow キャッシュ領域
[外付けHDD/NASの移動]    ───(3) ボリューム管理────────────► アクセス権一括復旧
```

### 1. XMLライブラリのインポート (`importXMLLibrary`)
- **操作**: 「保守」タブ > **「XMLライブラリのインポート...」** をクリックし、Stackroom の `Stackroom Library.xml` を選択します。
- **仕様**:
  - 書籍情報、フォルダ階層、スマート本棚の定義、レート評価、未読フラグなどを自動でパースし、ShelfRow のデータベースへ移行・マージします。
  - 旧アプリのバグや古い保存APIに起因する非標準な制御コード（`0x01`〜`0x1F` 等の XML 1.0 違反文字）を自動検知して高速クレンジングするため、エラーなく安全に読み込めます。

### 2. Stackroom サムネイルの移行 (`migrateLegacyThumbnails`)
- **操作**: 「保守」タブ > **「Stackroomサムネイルの移行...」** をクリックし、旧 Stackroom のライブラリフォルダ（`~/Library/Application Support/Stackroom/Stackroom Library/` など）を選択します。
- **仕様**:
  - 旧アプリが生成・蓄積してた表紙サムネイル（`[書籍ID]/thumbnail.jpg`）を、ShelfRow のプライベートキャッシュ領域へ一括物理コピーします。
  - **メリット**: 数万冊のアーカイブ（ZIP）を再解凍・CPU再抽出することなく、数秒〜数十秒で表紙表示が完了します。移行完了後は、旧 Stackroom フォルダを完全に削除しても問題ありません。

### 3. ボリューム管理・アクセス権の再割り当て (`manageVolumes`)
- **操作**: 「保守」タブ > **「ボリューム管理...」** をクリックします。
- **仕様**:
  - 外付けHDDの買い替え、マウントポイント変更、NASのパス変更があった場合、親ボリューム（ドライブ）を再選択することで全書籍のセキュリティスコープ付きブックマーク（Security-Scoped Bookmark）およびアクセス権を一括更新します。

### 4. サムネイルの一括生成 (`repairThumbnails`)
- **操作**: 「保守」タブ > **「サムネイルの一括生成...」** をクリックします。
- **仕様**:
  - サムネイルが未生成の書籍に加え、モノクロ画像や横長（見開き等）のサムネイルを自動検知し、連番ヒューリスティックに基づき最適なカラー縦長表紙を抽出・生成します。CPU コア数（最大8）まで並列実行します。
  - 問題のない縦長カラー表紙はそのまま使用（再生成しない）ため、中断しても再実行すれば続きから進みます。

### 5. ファイル名からのタイトル・属性補完 (`repairEmptyTitles`)
- **操作**: 「保守」タブ > **「ファイル名からタイトルを補完...」** をクリックします。
- **仕様**:
  - 「カスタマイズ」タブで設定したファイル名解析フォーマット（例: `(ジャンル)[作者]タイトル` や `@author`, `@title` など）に基づき、未入力のタイトル・作者・ジャンル等を一括補完します。

### 6. バックアップとリストア
- **操作**: 「保守」タブ > **「バックアップ」** で有効化し、バックアップ先フォルダを指定します。
- **仕様**:
  - 「今すぐバックアップ」で SwiftData DB、サムネイルキャッシュ、設定 plist を指定フォルダ内の `ShelfRowBackup` へ差分保存します。
  - 「バックアップからリストア」で保存時点の状態へ安全に上書き復元できます。

## ✨ 概要と主な特徴

* **Apple Silicon ネイティブ & 高速描画**: macOS 14 (Sonoma) 以降に最適化。SwiftUI ＋ SwiftData ＋ Metal/GPU 対応の軽量デコーディング。
* **大容量ライブラリ対応**: 2万冊を超える蔵書でも、`NSCache` によるオンデマンド・メモリ制御と遅延読み込みで滑らかなスクロール（60fps）を実現。
* **伝統的な 3 ペインデザイン**: 2010年代の macOS アプリが持っていた快適な視認性と直感的な操作感を再現。
* **外部ビューア専門化**: お気に入りのコミックビューア（EdgeView 等）や動画プレイヤーとシームレスに連携。

## 🛠 基本的な使い方

### 1. 画面構成 (3ペイン)
| ペイン | 主な機能・操作 |
| :--- | :--- |
| **左ペイン (サイドバー)** | 「すべての本」「未読の本」やカスタム本棚、条件指定のスマート本棚を表示。ドラッグ＆ドロップで並び替え可能。下部に `[+]`（本棚追加）と `[⚙️]`（環境設定）ボタンを配置。 |
| **中央ペイン (メイン)** | 書籍の一覧表示（大型グリッド表示／詳細リスト表示）。ソート、リアルタイム検索、未読・種別・レートによるマルチフィルタ。ダブルクリックで外部ビューアを起動。 |
| **右ペイン (インスペクター)** | 選択した書籍の詳細情報（タイトル・作者・ジャンル・レート・メモ等）の即時編集、表紙プレビュー、タグ検索チップ、Finder表示。 |

### 2. 書籍の新規登録 (ドラッグ & ドロップ)
- ZIPファイルや画像フォルダを中央ペインへ直接ドラッグ＆ドロップすると、環境設定のファイル名解析規則に従ってタイトル・作者・ジャンル等を自動判定してライブラリへ登録します。

### 3. スマート本棚の作成・編集
- サイドバー下部の `[+]` からスマート本棚を作成できます。
- 作者、ジャンル、キーワード、登録日、レート、未読条件を組み合わせて動的に書籍を自動収集します。

### 4. 外部ビューアの設定
- **⚙️ 環境設定 >「ビューア」**: スライドショーヘルパー（画像フォルダ用）や Zip アーカイブヘルパーを設定。
- **⚙️ 環境設定 >「ヘルパー」**: 拡張子（.cbz, .mov, .rar 等）ごとに割り当てるアプリケーションを指定。

## ☁️ iCloud 同期（複数の Mac でNASに格納された蔵書を共有する）

複数の Mac で同じ蔵書を扱えます。**⚙️ 環境設定 >「iCloud」** のスイッチで有効にします。
1台目になるMacと2台目以降のMacでできることに違いがあります。1台目のMacでNAS上に作ったライブラリを共有し、
2台目以降のMacでそれを操作する、という考えがベースにあります。同じLANに存在し、同じNASに繋がっていることが前提になります。
**全てのMacは同じAppleIDでiCloudに接続されていることが前提です**
**Macの上に直接置かれた蔵書は対象外です**
**この機能を用いて、1台目、2台目のマージはできません**
**iCloud に置くのは書誌情報だけ**で、重いもの・端末に固有のものは置きません。

```
  書籍の実体（ZIP・画像フォルダ）  ──►  NAS や外付けドライブ（iCloud には送らない）
  サムネイル                      ──►  各 Mac がそれぞれ生成・保持（iCloud には送らない）
  書誌情報（タイトル・作者・本棚・レート・未読・メモ…）  ──►  iCloud で同期
```

### 1. 同期されるもの・されないもの

| | 内容 | 理由 |
| :--- | :--- | :--- |
| **同期する** | 書籍レコード（タイトル・作者・ジャンル・キーワード・メモ・レート・未読・登録日・ページ数・ファイルの相対パス）、本棚とスマート本棚の定義、ボリュームの登録、表紙抽出の実施記録 | 端末をまたいで同じであるべき情報 |
| **同期しない** | **書籍の実体ファイル** | NAS にあるものをクラウドへ複製する意味がない |
| **同期しない** | **サムネイル画像** | 著作物であり、クラウドへ上げるべきものではない。容量も大きい |
| **同期しない** | **ファイルへのアクセス権**（Security-Scoped Bookmark） | 発行した Mac でしか通用しない。同期すると各端末が互いの解決できないアクセス権で上書きし合う |
| **同期しない** | ビューア・ヘルパーの割り当て、バックアップ先などの端末ごとの設定 | 端末の事情に属する |

アクセス権とサムネイルの取得状態は、iCloud に接続されない**別のデータベース**（`local.store`）に分けて保存しています。蔵書のデータベース（`default.store`）だけが iCloud に接続されます。

### 2. 有効にする手順

> [!IMPORTANT]
> **2 台の蔵書を突き合わせる処理（マージ）は行いません。** 同じ本が二重に登録される事故を避けるためです。「どちらの蔵書を残すか」を選ぶ形になります。

スイッチをオンにすると確認ダイアログが出ます。

1. **1 台目（この端末の蔵書を iCloud へ送る）**
   この Mac の蔵書が iCloud へ送られます。**最初の 1 台だけ**がこれを選びます。
2. **2 台目以降（iCloud の蔵書で置き換える）**
   この Mac の蔵書とアクセス権は**削除され**、iCloud の内容に置き換わります。**取り消せません。**

どちらを選んでもアプリが再起動します。蔵書のデータベースは開き方を変えるだけで中身は同じものを使うため、モードの切り替えには再起動が必要です（稼働中に差し替えると、表示中の書籍が足元から消えることになります）。

> [!WARNING]
> すでに iCloud に蔵書がある状態で「1 台目」を選ぶと、**同じ本が二重に登録されます**。2 台目以降では必ず「置き換える」を選んでください。

**置き換えを選んだ後は、ボリュームのアクセス権を与え直してください。** アクセス権は端末ごとのものなので iCloud からは来ません。**⚙️ 環境設定 >「保守」>「ボリューム管理...」** から NAS や外付けドライブを選び直します。これをしないと、書籍は一覧に並ぶのに開けない状態になります。

受信中は蔵書が空に見えます。件数の目安として、2 万冊規模で数分かかります。

### 3. 端末の役割

同期をオンにしたときの選択は記録され、現在のモード表示に出ます。

* **1 台目**: すべての項目が使えます。
* **2 台目以降**: 「iCloud へ全件を再送信」と「iCloud のデータを削除」は**表示されません**。どちらも全端末に及ぶ操作で、iCloud の内容を作った端末のものだからです。受け取っただけの端末では、他の端末の蔵書を壊す手段にしかなりません。

「iCloud のデータを削除」を実行すると役割の記録も消え、次にオンにしたときに選び直しになります。

### 4. 同期の状態を見る

**⚙️ 環境設定 >「iCloud」** に次が出ます。

* **状態**: iCloud が使えるかどうか。サインインしていない・制限されている場合はここに出ます。
* **アカウント**: 同期に使っている iCloud アカウントの識別子。文字列そのものに意味はありませんが、**2 台で同じ値なら同じアカウント**だと分かります。
* **現在のモード**: 「クラウド」か「ローカル」か。2 台目以降ならその旨も。
* **同期の進行**: `未送信 ○件 / 送信済み ○件 / この端末 ○件`。送受信が続いている間は回転アイコン、途切れれば「送受信完了」。

> [!NOTE]
> **「未送信 0 件」は iCloud に届いた証明ではありません。** この端末の記録でしかありません。他の端末の「この端末」の件数と突き合わせて、初めて揃ったと言えます。

**未受信の件数は表示できません。** 受信側は「まだ来ていないものが何件あるか」を知る手段を持たないためです（CloudKit は残り件数を教えてくれません）。

### 5. サインアウト・オフラインのとき

* **iCloud にサインインしていない**、または一時的に使えないとき、蔵書は**ローカルモードで開きます**。同期の設定自体は保持され、使えるようになれば戻ります。サインアウトで蔵書が消える経路には入りません。
* **スイッチをオフにする**と、この端末の蔵書は**そのまま残り**、iCloud への送信だけを止めます。iCloud 側の蔵書も消えません。オフにした瞬間にローカルを消すと、試しただけで蔵書を失う端末が出てしまうためです。
* オフラインで編集した内容は、接続が戻ったときに送られます。

> [!IMPORTANT]
> **同時編集は想定していません。** 1 人で複数の端末を使い分ける前提の作りです。2 台で同じ本を同時に編集した場合、後から届いた方が残ります。

### 6. プライバシーと容量

* 上がるのは**書誌情報**です。画像は上がりませんが、**タイトル・作者・メモ・ファイルの相対パス**は Apple のサーバに保存されます。何を所有しているかが分かる情報であることは意識しておいてください。気になる場合は、Apple ID 側で**高度なデータ保護（Advanced Data Protection）**を有効にするとエンドツーエンド暗号化されます。
* 保存先は**アプリ専用の領域（CloudKit プライベートデータベース）**です。iCloud Drive のフォルダには現れず、Finder からは見えません。
* 容量は、2 万冊規模で**数十 MB 程度**です。iCloud の空き容量を圧迫するものではありません。
* アプリの利用をやめるときは **「iCloud から完全に削除...」** で、この領域を完全に解放できます。この端末の蔵書・サムネイル・設定は残ります。

> [!WARNING]
> 削除を実行するときは、**先にすべての端末で同期をオフにしてください。** 同期がオンのままの端末が残っていると、その端末が同じ内容を再びアップロードします。

### 7. 蔵書が揃わないとき：「iCloud へ全件を再送信」

**⚙️ 環境設定 >「iCloud」>「全件を送信待ちに入れる...」**（1 台目のみ表示）

「未送信 0 件」と出ているのに他の端末に蔵書が揃わない、という状態のための機能です。

iCloud との同期は、レコードごとに「送信済みかどうか」の印を**この端末の中に**持っています。この印が iCloud の実態と食い違うと、送るものが無いと判断されたまま二度と追いつけません。全件を送信待ちに入れ直すことで、この食い違いを解消します。

* **蔵書の内容は変わりません。** 送信の印を立て直すだけで、iCloud に届くのは現在の蔵書そのままです。
* 件数が多いと時間がかかります。準備中は動作が重くなることがあります。
* 送信が終わってから、他の端末で「iCloud の蔵書で置き換える」を実行してください。

### 8. 困ったときは

| 症状 | 見るところ |
| :--- | :--- |
| 書籍は並ぶのに開けない | アクセス権が無い。「保守」>「ボリューム管理...」でボリュームを選び直す |
| 2 台目に蔵書が来ない | 1 台目の「未送信」が 0 になっているか。0 なのに来ないなら「全件を再送信」 |
| 表紙が出ない | サムネイルは iCloud では同期されない。[NAS 経由の配布](#-サムネイルの配布nas経由)を使うか、「保守」>「サムネイルの一括生成...」で端末ごとに作る |
| 同じ本が二重にある | 2 台目で「1 台目」を選んだ可能性。2 台目で「置き換える」をやり直す |
| 設定を変えても反映されない | モードの変更は再起動が必要。「今すぐ再起動」が出ていればそれを押す |

## 🖼 サムネイルの配布（NAS経由）

サムネイルは **iCloud には送りません。** 表紙画像は著作物であり、2 万冊規模では 1 GB 近くになるためです。その代わり、**書籍の実体が置いてある NAS 上のフォルダを配布経路として使います。**

これが無いと、2 台目は書誌情報を受け取っても表紙が出ず、NAS 上の ZIP を 19,000 冊分開き直すことになります。1 台目が既に済ませた仕事の焼き直しで、NAS の帯域も二重に使います。

```
   生成（1台目）              配布元（NAS）           取得（2台目以降）
ZIP → 表紙抽出 → キャッシュ  ─►  ShelfRowThumbnails/  ─►  キャッシュ
                                   ├─ 00/ … ff/  表紙の実体
                                   └─ 目録ファイル（どの本が、どの版で、何バイトか）
```

差分の判定に使うのは、**配布元に置かれた目録ファイル 1 つ**です。NAS のフォルダを一覧しに行くことも（2 万ファイルの列挙は取得より時間がかかります）、iCloud に問い合わせることもありません。

### 1. 設定する

**⚙️ 環境設定 >「保守」>「サムネイルの配布」**

1. **1 台目**で「選択...」を押し、NAS 上のフォルダを選びます。書籍と同じ共有の中が扱いやすく、既定では登録済みボリュームの直下に `ShelfRowThumbnails` を作る形を提案します。選んだフォルダは自動で配布元として初期化されます。
2. **「サムネイルを配布元へ登録」** を押します。この端末のサムネイルがすべて配布元へコピーされます。
3. **2 台目以降**でも同じフォルダを「選択...」で指定します。以降は自動で取得されます。

> [!NOTE]
> **「配布元へ登録」は iCloud を一切使いません。** 配布元フォルダには目録ファイルが置かれ、どの本の表紙がどの版で入っているかはそこに記録されます（2 万冊で約 1 MB）。他の端末はその 1 ファイルを読むだけで、取得すべきものが分かります。蔵書データベースには触れないため、同期には影響しません。

### 2. どの端末で何ができるか

配布は **iCloud 同期が有効なときだけ**動きます。差分を決める「表紙の版」は iCloud を通じてしか他の端末に届かないので、同期がオフの端末には配布元に置く相手も、置いてくれる相手もいません。

| | 1 台目 | 2 台目以降 | iCloud 同期オフ |
| :--- | :---: | :---: | :---: |
| 配布元フォルダの初期化 | ○ | × | × |
| サムネイルの一括生成 | ○ | ×（非表示） | ○（配布はしない） |
| 表示中の 1 冊の生成 | ○ | ○ | ○ |
| 配布元への一括登録 | ○ | ×（非表示） | × |
| 自分が生成した分の書き込み | ○ | ○ | × |
| 配布元からの取得 | ○ | ○ | × |
| 配布元の整理 | ○ | × | × |

**一括生成を 1 台目に限る**のは、2 台で同じ 2 万冊を抽出させないためです。一方、**表示中の 1 冊を生成することはどの端末でもでき、その結果は配布元へ上がります。** 今見ている本の表紙が無いときにそれを作れないのは不便ですし、作ったものは他の端末にも渡るべきものだからです。

### 3. 取得のしかた

* **一括取得**: この端末に無いサムネイルをまとめて取り込みます。初回は件数と容量を確認するダイアログが出ます（「今すぐ取得」「後で」「表示に応じて取得のみ」）。空き容量が足りない場合は取得できません。
* **差分取得**: 2 回目以降、少量であれば確認なしで静かに取得します。大量のとき（1 台目で表紙を大量に作り直した後など）は改めて確認します。
* **表示に応じた取得**: 一覧に出た本の表紙が無いとき、ZIP を開く前に配布元を見ます。配布元にあればそれを使い、無ければその場で生成します。

中断しても、次回は残りだけが対象になります。**NAS に届かないときは何も起きず、警告も出ません。** 出先でノートを開くのは日常であり、そのたびに警告を出すのは邪魔なだけだからです。

### 4. 設定項目

| 項目 | 内容 |
| :--- | :--- |
| 配布元フォルダ | 選択と状態表示（未設定 / 接続可 / 到達不可 / 別ライブラリ） |
| 自動取得 | オフにすると一括取得をせず、表示に応じた取得だけになります |
| 同時転送数 | 既定 6（2〜16）。小さなファイルの転送は待ち時間が支配的なので数本並べた方が速く、NAS の反応が鈍るなら下げます |
| 取得の状態 | 取得済み / 未取得 / 未登録 / 失敗 の件数 |

### 5. 注意点

> [!WARNING]
> **別のライブラリの配布元は使えません。** 配布元には目印のファイルが置かれ、ライブラリの識別子が記録されます。これが一致しないフォルダは拒否します。フォルダの指定を誤って、無関係な場所に 2 万ファイルを書き込む事故を防ぐためです。

* **配布元のサムネイルも著作物です。** iCloud に置かないという判断と同じ理由で、共有範囲にはご注意ください。
* サムネイルの破損チェックはファイルサイズの照合のみです。壊れた 1 枚の害は小さく、次の版で上書きされます。
* 取得に 3 回失敗した表紙は、いったん諦めます。1 台目で表紙を作り直して版が上がれば、自動的に対象へ戻ります。
* 容量の目安は 2 万冊で **0.6〜1.0 GB** です。初回は有線または Wi-Fi を推奨します。
