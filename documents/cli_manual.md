# ShelfRow コマンドライン マニュアル

ShelfRow は、コマンドを与えられたときだけコマンドラインツールとして振る舞う。別の実行ファイルは無く、アプリ本体と同じバイナリを呼ぶ。

```
/Applications/ShelfRow.app/Contents/MacOS/ShelfRow <コマンド> [引数...]
```

引数を与えなければ、これまでどおりウインドウが開く。

---

## 1. すぐ使うために

毎回フルパスを打つのは現実的ではないので、シェルの設定に別名を置く。

```bash
# ~/.zshrc
alias shelfrow='/Applications/ShelfRow.app/Contents/MacOS/ShelfRow'
```

以降、本書では `shelfrow` と書く。

```bash
shelfrow shelves
shelfrow add ~/Downloads/巻1.zip --shelf 未整理
```

---

## 2. コマンド

### `shelves` — シェルフの一覧

```
shelfrow shelves
```

登録されているシェルフを1行ずつ、**タブ区切り**で出す。

```
LO	通常	375件
hotmilk	通常	343件
未読	スマート	0件
```

| 列 | 内容 |
|---|---|
| 1 | シェルフ名 |
| 2 | `通常` または `スマート` |
| 3 | 所属している本の数 |

並び順はアプリのサイドバーと同じ（並び順 → 名前）。

タブ区切りにしてあるのは、名前に空白が入っていても壊れずに扱えるようにするため。

```bash
# 通常シェルフの名前だけを取り出す
shelfrow shelves | awk -F'\t' '$2 == "通常" { print $1 }'

# 本が入っていないシェルフを探す
shelfrow shelves | awk -F'\t' '$3 == "0件" { print $1 }'
```

シェルフが1つも無い場合は、どの蔵書を読んだかを添えて知らせる。

```
シェルフはありません。（読んだ蔵書: /Users/you/Library/Containers/...）
```

これは「空のライブラリ」と「別のライブラリを読んでしまった」を区別するためにある。署名済みのアプリと、Xcode でビルドしたアプリは蔵書の置き場所が違う。

### `add` — ライブラリに登録する

```
shelfrow add <ファイル>... [--shelf <名前>]
```

**アプリの画面へドラッグ&ドロップしたときとまったく同じ登録を行う。**

- ファイル名から、環境設定 > カスタマイズの書式に従ってタイトル・作者などを取り出す
- ZIP や画像フォルダはページ数を数え、書式が種類を指定していなければページ数から種類を決める
- すでに登録されている本は二重にせず、アクセス権だけを更新する
- `--shelf` を付けると、その通常シェルフにも入れる

| 指定 | 短縮 | 内容 |
|---|---|---|
| `--shelf <名前>` | `-s` | 登録先の通常シェルフ。省略するとライブラリにだけ入る |

ファイルは何個でも並べられる。

```bash
shelfrow add /Volumes/Files/本/巻1.zip /Volumes/Files/本/巻2.zip --shelf LO
```

結果は1件ずつ出る。

```
登録: 巻1.zip → LO
更新: 巻2.zip → LO
```

`登録` は新しく入った本、`更新` はすでにあった本である。

```bash
# フォルダの中の ZIP をまとめて入れる
find /Volumes/Files/新着 -name '*.zip' -print0 | xargs -0 shelfrow add --shelf 未整理
```

### `help` — 使い方

```
shelfrow help
shelfrow --help
shelfrow -h
```

## 3. 知っておく必要のある2つの制約

### 3.1 登録済みのボリュームの中にあるファイルしか追加できない

アプリはサンドボックスの中で動いている。**パスを渡されただけでは、そのファイルを開く権限が無い。** ファイルに手が届くのは、ライブラリが持っているボリュームのアクセス権（Security-Scoped Bookmark）を通したときだけである。

つまり、

- すでに登録済みの NAS や外付けドライブの中のファイル → **追加できる**
- まだ一度もアプリに見せていない場所のファイル → **追加できない**

後者はこう出る。

```
見つかりません: /Volumes/新しいHDD/本.zip（このファイルのあるボリュームは登録されていません。一度アプリの画面へドラッグしてください）
```

新しい場所を使い始めるときは、**最初の1回だけアプリの画面へドラッグする。** それで権限が保存され、以降は同じボリュームの中のファイルをコマンドラインから追加できる。

これは実装の都合ではなく、サンドボックスが権限を与える形そのものである。

### 3.2 `add` はアプリを終了してから

```
ShelfRow が起動しています。終了してから実行してください。
```

同じデータベースを2つのプロセスが同時に書くのを避けるため、`add` はアプリの起動中は実行を断る。`shelves` は読むだけなので、起動中でも使える。

---

## 4. iCloud との関係

コマンドラインでは iCloud 同期を動かさない。一瞬で終わるプロセスが同期を始めても、それを見届けられないためである。

**追加した本が失われることはない。** 変更は Core Data の履歴に記録され、次にアプリを起動したときに iCloud へ送られる。

---

## 5. 終了コード

スクリプトから使うときのために、`sysexits` の慣習に従う。

| コード | 名前 | 意味 |
|---|---|---|
| 0 | — | 成功 |
| 64 | `EX_USAGE` | 引数の誤り（ファイル名が無い、知らない指定、など） |
| 65 | `EX_DATAERR` | 指定されたシェルフやファイルが扱えない |
| 69 | `EX_UNAVAILABLE` | アプリが起動中で実行できない |
| 74 | `EX_IOERR` | 蔵書データベースを開けない・保存できない |

複数のファイルを渡して一部だけ失敗した場合は、成功した分は登録したうえで 65 を返す。

```bash
if shelfrow add "$file" --shelf 未整理; then
    echo "入った"
else
    echo "入らなかった（終了コード $?）"
fi
```

結果は標準出力、問題は標準エラー出力に出る。

```bash
shelfrow shelves 2>/dev/null   # 問題は捨てて一覧だけ使う
```

## 6. シェルフ名の指定について

名前は人が付けるものなので、次の順で探す。

1. 完全に一致するもの
2. 無ければ、大文字小文字を無視して一致するもの

うまくいかない場合は、3つを区別して伝える。

| 出力 | 意味 |
|---|---|
| `シェルフが見つかりません: 名前（shelves で一覧を確認できます）` | その名前のシェルフが無い |
| `「名前」はスマートシェルフです。…` | スマートシェルフは条件で自動的に集まるので、手で追加できない |
| `「名前」という名前のシェルフが2個あります。…` | 同名のシェルフが複数あり、どちらか決められない |

スマートシェルフへ手で追加しないのは、ドラッグ&ドロップと同じ規則である。

---

## 7. 困ったとき

| 症状 | 見るところ |
|---|---|
| `シェルフはありません` と出る | 出力の「読んだ蔵書」を見る。Xcode でビルドしたアプリと、`/Applications` の署名済みアプリは蔵書の置き場所が別 |
| `見つかりません` と出る | ボリュームが未登録か、マウントされていない。Finder でそのパスが開けるか確認する |
| `登録の対象外です` と出る | 環境設定 > ヘルパーに拡張子が登録されていない。ZIP とフォルダは最初から対象 |
| `ShelfRow が起動しています` | `add` はアプリを終了してから。`shelves` は起動中でも使える |
| ウインドウが開いてしまう | コマンド名の綴りを確認する。知らない語は「コマンドではない」と判断され、アプリが起動する |

---

## 8. ドラッグ&ドロップとの関係

どちらも同じ1本の実装（`LibraryRegistrar`）を呼ぶ。重複の扱い、ボリュームの作成、ファイル名の解析、種類の自動判定、シェルフへの追加は完全に同じ動作になる。

画面から操作したときだけ起きることが3つある。いずれも表示の都合であり、登録される内容は変わらない。

- 登録中の進捗表示
- 登録し終えた本を選択状態にする
- ページ数を後から数えて反映する（コマンドラインでは、その場で数えてから終了する）

設計上の位置づけは `documents/design_document.md` の第16章を参照。
