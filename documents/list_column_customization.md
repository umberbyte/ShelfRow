# リストビューのカラム設定（2026-09-23）

## 対象

リストビューのカラムは、表示／非表示、並び順、列幅を利用者が調整できる。ヘッダーと各行は同じ `LibraryListColumn` 配列を参照するため、並び順と幅は常に一致する。列間隔と実効左右余白も `LibraryListLayout` で共有する。保存済みの列幅の合計が表示領域より細い場合も、ヘッダーと行のコンテナをともに表示領域いっぱいの先頭揃えにして、縮小表示でヘッダーだけが中央へ移動することを防ぐ。

対象カラムは、未読、種類、タイトル、レート、作者、ジャンル、関連、キーワードA、キーワードB、読んだ日、登録日である。タイトルは常に表示し、その他はヘッダーの右クリックメニューから表示／非表示を切り替える。

## 見出しと並び替え

- 見出しは列内で中央揃えとし、ソート方向の矢印も文字と一緒に中央へ配置する。
- 見出しのクリックで、その項目を昇順／降順にソートする。
- 見出し本体を左右へドラッグすると列を入れ替える。
- 非表示の列も完全な並び順の中に残すため、再表示したときは以前の位置へ戻る。

並び順は「カラムの並び順を全体に適用する」がONなら全体共通、OFFなら「すべての本」「未読の本」「各シェルフ」ごとに保存する。OFFからONへ戻すときは、シェルフ別の並び順を削除する警告を表示し、実行するOKボタンは破壊的操作として赤字にする。

## 列幅

幅を変更できる列は、見出し右端の境界を左右へドラッグする。右へ動かすと拡大し、左へ動かすと縮小する。ドラッグ中はヘッダーと全行へ即時反映し、ドラッグ終了時に保存する。

次の列は、表示要素と見出し、ソート矢印に必要な領域を安定して確保するため固定幅とする。

| カラム | 通常表示の幅 | 内容 |
|---|---:|---|
| 未読 | 44 pt | 見出し、ソート矢印、未読マーク |
| 種類 | 44 pt | 見出し、ソート矢印、種類アイコン |
| レート | 92 pt | 見出し、ソート矢印、5個の★ |
| 読んだ日 | 96 pt | 見出し、ソート矢印、日付 |
| 登録日 | 96 pt | 見出し、ソート矢印、日付 |

固定幅列にはリサイズ境界と左右リサイズカーソルを表示しない。以前の版で保存された幅が存在しても固定幅を優先する。列の位置は固定せず、ほかの列と同様に並べ替えられる。

タイトル、作者、ジャンル、関連、キーワードA、キーワードBは可変幅である。タイトルは幅が未保存なら残り領域を使う柔軟列として扱い、一度変更した後は保存幅を使用する。保存値は60〜1,200 ptの範囲に補正する。

「表示を縮小」がONの場合、通常表示の幅と保存幅を75%に縮小して描画する。保存値自体は通常表示の論理ポイントで保持するため、表示モードを切り替えても設定値は変化しない。

## 幅の保存単位

「カラムの幅を全体に適用する」がONなら全体共通、OFFなら「すべての本」「未読の本」「各シェルフ」ごとに保存する。個別幅がまだない画面では全体幅へフォールバックする。

OFFからONへ戻すときは、シェルフ別の幅を削除する警告を表示する。キャンセルでは設定を維持し、赤字のOKを選んだ場合だけ個別幅を削除して全体幅へ統一する。非表示列の保存幅は削除しないため、再表示後も以前の幅を利用できる。

## 永続化キー

| UserDefaultsキー | 内容 |
|---|---|
| `listVisibleColumns` | 表示するカラム |
| `listColumnOrderAppliesGlobally` | 並び順を全体共通にするか |
| `listColumnOrderGlobal` | 全体共通の並び順 |
| `listColumnOrdersByCollection` | 画面／シェルフ別の並び順 |
| `listColumnWidthAppliesGlobally` | 幅を全体共通にするか |
| `listColumnWidthsGlobal` | 全体共通の可変列幅 |
| `listColumnWidthsByCollection` | 画面／シェルフ別の可変列幅 |

画面／シェルフ別のキーは `library.all`、`library.unread`、`shelf.<UUID>` を使用する。並び順はカラム名の配列、幅はカラム名と論理ポイントの辞書をJSONで保存する。

## レートの直接編集

リストのレート列は5個の★をボタンとして操作でき、変更時にSwiftDataへ保存する。現在の評価と同じ★をクリックすると0（評価なし）に戻り、同じ★をもう一度クリックするとその評価を再登録する。右インスペクタも同じ `RatingView` と選択規則を使う。

行全体のクリック判定は、レート列以外のセルに `PrimaryClickOverlay` を配置する。これにより、行の単クリック選択とダブルクリック起動を維持しながら、★ボタンへポインターイベントを渡す。

## 実装と検証

- `LibraryColumnOrder.swift`: 完全な並び順、移動、画面／シェルフ別キー、JSON保存
- `LibraryColumnWidth.swift`: 固定列、既定幅、可変幅の範囲補正、画面／シェルフ別JSON保存
- `ContentView.swift`: ヘッダー、ドラッグ操作、スコープ選択、UserDefaultsへの保存
- `LibraryListRow.swift`: ヘッダーと共有する列定義による行レイアウト、レート編集
- `PreferencesView.swift`: 並び順と幅の全体適用スイッチ、個別設定削除の警告
- `RatingView.swift`: ★ボタンと評価解除／再登録

Swift Testingでは、欠損・重複した並び順の修復、列移動、スコープ別の並び順、幅のJSON往復、範囲補正、スコープ別の幅、ドラッグ方向、固定幅対象を確認する。列幅機能追加時の全テスト87件、方向修正を含むv2.2ビルド4の全テスト88件とmacOS UIテスト5件は成功している。固定幅化後は列幅テスト5件とDebugビルドが成功している。
